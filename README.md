# Support Ticket Management API

A REST API for managing support users, customer tickets, ticket assignments, and comments.

## Overview

The API currently supports:

- Creating and browsing users
- Creating, filtering, updating, and deleting tickets
- Assigning tickets to agents or managers
- Viewing tickets belonging to a customer or assigned to an agent
- Adding and listing ticket comments
- Viewing ticket status statistics

Authentication and authorization middleware are not implemented yet. Role checks are applied by selected controller operations.

## Stack

- Node.js
- Express 5
- PostgreSQL 16
- Drizzle ORM

## Requirements

- Node.js 18 or newer
- npm
- Docker Desktop with Docker Compose

## Installation

### 1. Install dependencies

```bash
npm install
```

### 2. Start PostgreSQL

```bash
docker compose up -d
```

The included Compose configuration reads the database settings from your local `.env` file. Do not commit `.env` or place real credentials in documentation.

### 3. Create your local environment file

Copy the example environment file and update the values as needed:

```bash
cp .env.example .env
```

The example file contains placeholders only:

| Setting        | Value                           |
| -------------- | ------------------------------- |
| `DB_USER`      | Your PostgreSQL username        |
| `DB_PASSWORD`  | Your PostgreSQL password        |
| `DB_NAME`      | Your database name              |
| `DB_PORT`      | PostgreSQL port, usually `5432` |
| `DATABASE_URL` | PostgreSQL connection URL       |

Edit `.env` with your own values. For example:

```env
DB_USER=your_db_user
DB_PASSWORD=your_secure_password
DB_NAME=your_database_name
DB_PORT=5432
DATABASE_URL=postgresql://${DB_USER}:${DB_PASSWORD}@localhost:${DB_PORT}/${DB_NAME}
```

Use URL-encoded values if your database username or password contains special characters. The `.env` file is ignored by Git; keep credentials there rather than in `README.md`, `docker-compose.yml`, or source files.

### 4. Start the API

```bash
node src/server.js
```

The API is available at:

```text
http://localhost:8000
```

There are currently no automated test or migration scripts in `package.json`.

## Data Model

### User roles

Users have one of these roles:

- `customer`
- `agent`
- `manager`

### Ticket statuses

- `open`
- `in_progress`
- `resolved`
- `closed`

### Ticket priorities

- `low`
- `medium`
- `high`
- `urgent`

## API Reference

All request and response bodies use JSON. The examples below omit fields whose values are generated by the database, such as IDs and timestamps.

### Users

#### Create a user

```http
POST /users
Content-Type: application/json
```

Request:

```json
{
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "role": "customer"
}
```

Response `201 Created`:

```json
{
  "message": "New user created successfully",
  "user": {
    "id": 1,
    "name": "Ada Lovelace",
    "email": "ada@example.com",
    "role": "customer",
    "created_at": "2026-09-10T12:00:00.000Z"
  }
}
```

`role` must be `customer`, `agent`, or `manager`. Email addresses must be unique.

#### List users

```http
GET /users
```

Returns up to 50 users.

#### Get a user

```http
GET /users/:id
```

#### List a customer's tickets

```http
GET /users/:id/tickets
```

The user must have the `customer` role. Returns up to 50 tickets.

Response `200 OK`:

```json
{
  "message": "Tickets fetched successfully",
  "count": 1,
  "role": "customer",
  "tickets": []
}
```

### Tickets

#### Create a ticket

```http
POST /tickets
Content-Type: application/json
```

Request:

```json
{
  "title": "Unable to sign in",
  "description": "The password reset link is not working.",
  "priority": "high",
  "customer_id": 1
}
```

The referenced user must have the `customer` role.

Response `201 Created`:

```json
{
  "message": "New ticket raised successfully",
  "newTicket": {
    "id": 1,
    "title": "Unable to sign in",
    "description": "The password reset link is not working.",
    "status": "open",
    "priority": "high",
    "customer_id": 1,
    "assigned_agent_id": null,
    "created_at": "2026-09-10T12:00:00.000Z",
    "updated_at": "2026-09-10T12:00:00.000Z"
  }
}
```

#### List tickets

```http
GET /tickets
```

Optional query parameters:

| Parameter     | Description                                    | Default |
| ------------- | ---------------------------------------------- | ------- |
| `status`      | `open`, `in_progress`, `resolved`, or `closed` | None    |
| `priority`    | `low`, `medium`, `high`, or `urgent`           | None    |
| `customer_id` | Filter by customer ID                          | None    |
| `agent_id`    | Filter by assigned agent ID                    | None    |
| `page`        | Page number                                    | `1`     |
| `limit`       | Number of results per page                     | `10`    |

Example:

```http
GET /tickets?status=open&priority=urgent&page=1&limit=10
```

Response `200 OK`:

```json
{
  "data": [],
  "page": 1,
  "limit": 10,
  "total": 0,
  "totalPages": 0
}
```

#### Get a ticket

```http
GET /tickets/:id
```

#### Update a ticket

```http
PATCH /tickets/:id
Content-Type: application/json
```

At least one supported field is required. Any combination may be supplied:

```json
{
  "status": "in_progress",
  "priority": "urgent",
  "assigned_agent_id": 2
}
```

Set `assigned_agent_id` to `null` to unassign the ticket. Assignments may target users with the `agent` or `manager` role.

Response `200 OK`:

```json
{
  "message": "ticket updated successfully",
  "updatedTicket": {}
}
```

#### Delete a ticket

```http
DELETE /tickets/:id
```

Response `200 OK`:

```json
{
  "message": "Ticket 1 deleted successfully"
}
```

#### Get ticket statistics

```http
GET /tickets/stats
```

Response `200 OK`:

```json
{
  "message": "Ticket statistics retrieved successfully",
  "stats": {
    "total": 10,
    "open": 4,
    "inProgress": 3,
    "resolved": 2,
    "closed": 1
  }
}
```

### Comments

#### List comments for a ticket

```http
GET /tickets/:id/comments
```

Returns up to 50 comments ordered from oldest to newest.

Response `200 OK`:

```json
{
  "message": "Comments fetched successfully",
  "count": 1,
  "comments": []
}
```

#### Add a comment to a ticket

```http
POST /tickets/:id/comments
Content-Type: application/json
```

Request:

```json
{
  "user_id": 2,
  "message": "We are investigating this issue."
}
```

Response `201 Created`:

```json
{
  "message": "New comment created",
  "newComment": {}
}
```

### Agents

#### List tickets assigned to an agent

```http
GET /agents/:id/tickets
```

The user must have the `agent` role. Returns up to 50 tickets.

Response `200 OK`:

```json
{
  "message": "Tickets fetched successfully",
  "count": 1,
  "role": "agent",
  "tickets": []
}
```

## Error Responses

Most errors use this shape:

```json
{
  "error": "Description of the error"
}
```

| Status                      | Meaning                                         |
| --------------------------- | ----------------------------------------------- |
| `200 OK`                    | Request succeeded                               |
| `201 Created`               | Resource created                                |
| `400 Bad Request`           | Invalid input or unsupported value              |
| `404 Not Found`             | User, ticket, or related resource was not found |
| `409 Conflict`              | Duplicate email address                         |
| `500 Internal Server Error` | Unexpected server or database error             |
